    1. Create `web/src/lib/dal.ts` — Data Access Layer:
       ```typescript
       import 'server-only'
       import { cache } from 'react'
       import { auth } from '@/lib/auth'
       import { query } from '@/lib/db'
       import { redirect } from 'next/navigation'

       export const verifySession = cache(async () => {
         const session = await auth()
         if (!session?.user?.id) {
           redirect('/login')
         }
         return {
           isAuth: true,
           userId: session.user.id,
           role: session.user.role as 'gestor' | 'vendedor',
           email: session.user.email,
           name: session.user.name
         }
       })

       // Helper: get auth for API routes (returns null instead of redirect)
       export async function getApiSession() {
         const session = await auth()
         if (!session?.user?.id) return null
         return {
           userId: session.user.id,
           role: session.user.role as 'gestor' | 'vendedor'
         }
       }

       // Helper: build vendedor filter clause for leads queries
       export function buildVendedorFilter(role: string, userId: string, paramIndex: number) {
         if (role === 'gestor') return { clause: '', params: [], nextIndex: paramIndex }
         return {
           clause: `AND la.vendedor_id = $${paramIndex}`,
           params: [userId],
           nextIndex: paramIndex + 1
         }
       }
       ```

    2. Protect ALL existing API routes. For each route file, add at the TOP of the GET handler:
       ```typescript
       import { getApiSession } from '@/lib/dal'

       // At start of GET handler:
       const session = await getApiSession()
       if (!session) {
         return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
       }
       ```

       NOTE: The middleware already blocks unauthenticated requests, but defense-in-depth is critical. API routes MUST check auth independently.

    3. For the main leads route (`web/src/app/api/leads/route.ts`), add role-based filtering:
       - If session.role === 'gestor': Return all leads (current behavior)
       - If session.role === 'vendedor': Add JOIN to lead_assignments and filter by vendedor_id
       - Modify the query to LEFT JOIN lead_assignments and add WHERE clause for vendedor role
       - Keep all existing filter logic (estado, search, maxPropostas, etc.) working alongside the vendedor filter

    4. For lead detail routes (`/api/leads/[cnpj]/*`), add ownership check for vendedor role:
       - If vendedor, verify the lead_cnpj is assigned to them via lead_assignments table
       - If not assigned, return 403 Forbidden
       - If gestor, allow access to any lead

    5. For chart/filter/stats/dashboard routes: Add auth check but NO role filtering (these show aggregate data visible to all authenticated users). This is intentional -- vendedor can see overall market stats but only their assigned leads in the leads table.
