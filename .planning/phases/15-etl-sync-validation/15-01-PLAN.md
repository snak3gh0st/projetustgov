**Date parser helper (not exported — internal to this file):**
```typescript
function parseBRDate(val: string | null | undefined): string | null {
  if (!val || !val.trim()) return null
  const trimmed = val.trim()
  const parts = trimmed.split('/')
  if (parts.length === 3 && parts[0].length <= 2) {
    // DD/MM/YYYY -> YYYY-MM-DD
    return `${parts[2]}-${parts[1].padStart(2, '0')}-${parts[0].padStart(2, '0')}`
  }
  return trimmed  // assume already ISO if not DD/MM/YYYY
}
```

**Main function — `syncProjetosExecucao()`:**

The function MUST follow this exact algorithm:

**STEP A: Stream siconv_proposta.csv.zip, build OSC-only propostaMap**
- Call `downloadAndStreamCSV(PROPOSTA_URL, onRow)`
- Inside `onRow`: increment `stats.proposta_rows_scanned`
- Filter: check multiple possible column names for the OSC indicator. The filter must try these column names in order: `NATUREZA_JURIDICA`, `NATUREZA_JURIDICA_PROPONENTE`, `NAT_JUR`. The OSC filter string to match (case-insensitive) is: rows where the column value contains any of these substrings: `'associa'`, `'fundacao'`, `'organiza'`, `'coopera'`, `'instituto'`, or where `TIPO_INSTRUMENTO` (if present) contains `'osc'`.
- **CRITICAL: If the OSC filter column is not found among the expected names, log a WARNING and print the first row's keys for debugging, then proceed trying a broader fallback: check if column `TIPO_INSTRUMENTO` exists and filter on `includes('osc')` (case-insensitive). If neither column works, log an ERROR with all available column names and return early with stats.**
- For rows passing the filter: call `cleanCNPJ(row.CNPJ_PROPONENTE || row.IDENTIF_PROPONENTE)` — try both column names. If cnpj is null, skip the row.
- Add to Map: `propostaMap.set(row.ID_PROPOSTA, { cnpj, nome_proponente: fixText(row.NM_PROPONENTE || row.NOME_PROPONENTE), objeto: fixText(row.OBJETO_PROPOSTA || row.DESC_OBJETO), uf: row.UF_PROPONENTE || row.UF, municipio: fixText(row.MUNICIPIO_PROPONENTE || row.MUNIC_PROPONENTE) })`
- After streaming: log `propostaMap.size` and `stats.osc_rows_kept`. Log `process.memoryUsage().heapUsed / 1024 / 1024` as memory_peak_mb.
- **Memory guard**: If `process.memoryUsage().heapUsed > 900 * 1024 * 1024` (900MB), log a CRITICAL warning. Do NOT implement two-pass in this plan — just log the warning so it is visible in cron logs.

**STEP B: Stream siconv_convenio.csv.zip, filter "em execucao", join with propostaMap**
- Call `downloadAndStreamCSV(CONVENIO_URL, onRow)`
- Inside `onRow`: increment `stats.convenio_rows_scanned`
- Filter: `(row.SITUACAO_CONVENIO || row.SIT_CONVENIO || '').toLowerCase().includes('execu')`. If no match, return early.
- Increment `stats.em_execucao_rows`
- Look up `propostaMap.get(row.ID_PROPOSTA)`. If not found, increment `stats.join_miss_count` and return (LEFT JOIN with miss counting).
- Build `ExecucaoRecord` from the row + proposta info:
  - `nr_convenio`: `row.NR_CONVENIO` (string, required)
  - `id_proposta`: `row.ID_PROPOSTA`
  - `situacao`: `fixText(row.SITUACAO_CONVENIO || row.SIT_CONVENIO)`
  - `modalidade`: `fixText(row.MODALIDADE || row.MOD_CONV)`
  - `cnpj`: from propostaMap
  - `nome_proponente`, `objeto`, `uf`, `municipio`: from propostaMap
  - Financial fields — use `parseBRNumber` on each. Try multiple column name variants:
    - `valor_global`: `parseBRNumber(row.VL_GLOBAL_CONV || row.VL_GLOBAL)`
    - `valor_repasse`: `parseBRNumber(row.VL_REPASSE_CONV || row.VL_REPASSE)`
    - `valor_desembolsado`: `parseBRNumber(row.VL_DESEMBOLSADO_CONV || row.VL_DESEMBOLSADO)`
    - `saldo_conta`: `parseBRNumber(row.VL_SALDO_CONTA_CORRENTE || row.VL_SALDO_REMAN_TESOURO)`
    - `valor_empenhado`: `parseBRNumber(row.VL_EMPENHADO_CONV || row.VL_EMPENHADO)`
  - Date fields — use `parseBRDate`:
    - `data_assinatura`: `parseBRDate(row.DT_ASSINATURA_CONV || row.DT_ASSINATURA)`
    - `data_inicio_vigencia`: `parseBRDate(row.DT_INICIO_VIGENCIA || row.DT_INI_VIG)`
    - `data_fim_vigencia`: `parseBRDate(row.DT_FIM_VIGENCIA || row.DT_FIM_VIG)`
  - Computed fields:
    - `pct_execucao`: if `valor_repasse > 0`: `Math.round((valor_desembolsado / valor_repasse) * 10000) / 100`, else `null`
    - `dias_em_execucao`: if `data_inicio_vigencia` is truthy: `Math.floor((Date.now() - new Date(data_inicio_vigencia).getTime()) / 86_400_000)`, else `null`
    - `dias_ate_vencimento`: if `data_fim_vigencia` is truthy: `Math.floor((new Date(data_fim_vigencia).getTime() - Date.now()) / 86_400_000)`, else `null`
    - `alerta_desembolso`: `valor_desembolsado < 0` (literal check — Pitfall 7 warns this may never be true, but we store the flag as-is; Phase 16 will refine after client confirmation)
    - `verificar_saldo`: `valor_desembolsado > 0 && saldo_conta <= 0`
- Push to `records` array.
- After streaming, set `stats.joined_rows = records.length`

**STEP C: Bulk UPSERT into projetos_execucao**
- Acquire a pg client from `getPool().connect()`
- Wrap in `try/finally` — **ALWAYS** release client in `finally`
- **Log first 3 records** for debugging (column names, values) so CSV column mapping can be verified
- **Log first row's raw CSV keys** from both proposta and convenio streams (capture in STEP A/B using a debug flag: `if (stats.proposta_rows_scanned === 1) console.log('[execucao-sync] Proposta CSV headers:', Object.keys(row))`)
- Iterate over `records` array. For each record, execute this parameterized query:

```sql
INSERT INTO projetos_execucao (
  nr_convenio, id_proposta, situacao, modalidade,
  cnpj, nome_proponente, objeto, uf, municipio,
  valor_global, valor_repasse, valor_desembolsado, saldo_conta, valor_empenhado,
  data_assinatura, data_inicio_vigencia, data_fim_vigencia,
  pct_execucao, dias_em_execucao, dias_ate_vencimento,

ON CONFLICT (nr_convenio) DO UPDATE SET
  id_proposta          = EXCLUDED.id_proposta,

  dias_em_execucao     = EXCLUDED.dias_em_execucao,
  dias_ate_vencimento  = EXCLUDED.dias_ate_vencimento,
  alerta_desembolso    = EXCLUDED.alerta_desembolso,
  verificar_saldo      = EXCLUDED.verificar_saldo,
  synced_at            = NOW()
```

- Parameters array: `[rec.nr_convenio, rec.id_proposta, rec.situacao, rec.modalidade, rec.cnpj, rec.nome_proponente, rec.objeto, rec.uf, rec.municipio, rec.valor_global, rec.valor_repasse, rec.valor_desembolsado, rec.saldo_conta, rec.valor_empenhado, rec.data_assinatura, rec.data_inicio_vigencia, rec.data_fim_vigencia, rec.pct_execucao, rec.dias_em_execucao, rec.dias_ate_vencimento, rec.alerta_desembolso, rec.verificar_saldo]`
- Track insert vs update: check `result.rowCount` — if the insert's `ON CONFLICT` fires, it counts as an update. Use a heuristic: run a `SELECT COUNT(*) FROM projetos_execucao` before and after the UPSERT loop to determine new rows vs updated rows.
- Wrap each UPSERT in try/catch. On error, increment `stats.errors`, log the error with the record's `nr_convenio`, and continue to the next record.

**STEP D: Log to cron_sync_log**
- After the UPSERT loop, insert one row into `cron_sync_log`:

- Parameters: `[stats.inserted, stats.updated, stats.errors, Date.now() - startTime, stats.join_miss_count]`
