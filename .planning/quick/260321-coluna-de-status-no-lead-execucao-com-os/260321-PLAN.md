  <files>web/src/app/api/execucao/route.ts</files>
  <action>
Adicione um campo `crm_status` na resposta agrupada por CNPJ de `/api/execucao` usando `vendedor_projetos` como fonte.

Implementação esperada:
1. Atualize a interface `ExecucaoAggRow` para incluir `crm_status: string`.
2. No SELECT principal, adicione uma subquery correlacionada que busque o status mais avançado para `pe.cnpj` em `vendedor_projetos`.
3. Normalize `NULL` e `Nao Contatado` para `Não Contatado`.
4. Use a mesma ordem de prioridade já documentada em `web/src/lib/repo-sync.ts`: `Fechado` > `Aguardando Closer` > `Proposta` > `Retorno` > `Ainda Não` > `Não Contatado`. Se aparecerem `Quente`, `Muito Quente` ou `Telefone Invalido`, preserve-os e coloque-os depois dos status prioritários explícitos, sem sobrescrever `Fechado/Aguardando Closer/Proposta/Retorno/Ainda Não`.
5. Empate: use `updated_at DESC` como critério secundário para pegar o status mais recente.

Formato sugerido:
```sql
COALESCE((
  SELECT CASE
    WHEN COALESCE(vp.status_contato, 'Não Contatado') IN ('Nao Contatado', 'Não Contatado') THEN 'Não Contatado'
    ELSE vp.status_contato
  END
  FROM vendedor_projetos vp
  WHERE vp.cnpj = pe.cnpj
  ORDER BY CASE ... END, vp.updated_at DESC
  LIMIT 1
), 'Não Contatado') AS crm_status
```

Não altere filtros, KPIs, tags, `last_synced`, slide-over, nem a forma como contatos são carregados. Esta task só adiciona o campo agregado necessário para a nova coluna.
