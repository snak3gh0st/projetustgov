**GET handler with role guard:**
- Call `getApiSession()` as the FIRST statement
- If `!session`, return `{ error: 'Unauthorized' }` with status 401
- If `session.role !== 'gestor' && session.role !== 'coordenador'`, return `{ error: 'Unauthorized' }` with status 401
- IMPORTANT: Use 401 (not 403) for role failures — this is the project convention

**Dynamic WHERE conditions (same pattern as /api/leads/route.ts):**
- Parse `searchParams`: `search` (string), `uf` (string), `alert_only` (boolean string)
- Initialize: `const conditions: string[] = ['1=1']`, `const params: unknown[] = []`, `let paramIndex = 1`
- If `search`: strip punctuation with `search.replace(/[.\-\/]/g, '')`, push two conditions:
  `(pe.nome_proponente ILIKE $${paramIndex} OR pe.cnpj LIKE $${paramIndex + 1})` with params `%${search}%` and `%${searchClean}%`, increment paramIndex by 2
- If `uf`: push `pe.uf = $${paramIndex++}` with param `uf.toUpperCase()`
- If `alert_only === 'true'`: push `(pe.alerta_desembolso = TRUE OR pe.verificar_saldo = TRUE)` (no param needed — literal SQL)

**Main GROUP BY query (CRITICAL — all computations in SQL, not JavaScript):**
```sql
SELECT
  pe.cnpj,
  MAX(pe.nome_proponente)                                  AS nome_proponente,
  MAX(pe.uf)                                               AS uf,
  MAX(pe.municipio)                                        AS municipio,
  COUNT(*)::INT                                            AS total_projetos,
  SUM(pe.valor_repasse)                                    AS total_repasse,
  SUM(pe.valor_desembolsado)                               AS total_desembolsado,
  SUM(pe.saldo_conta)                                      AS total_saldo,
  CASE
    WHEN SUM(pe.valor_repasse) > 0
    THEN ROUND(SUM(pe.valor_desembolsado) / SUM(pe.valor_repasse) * 100, 1)
    ELSE NULL
  END                                                      AS pct_execucao_ponderado,
  BOOL_OR(pe.alerta_desembolso)                            AS tem_alerta,
  BOOL_OR(pe.verificar_saldo)                              AS tem_verificar_saldo,
  MIN(pe.data_fim_vigencia)                                AS data_fim_vigencia_mais_proxima,
  MIN(
    EXTRACT(DAY FROM pe.data_fim_vigencia - NOW())::INT
  )                                                        AS dias_ate_vencimento_min,
  MAX(
    GREATEST(0, EXTRACT(DAY FROM NOW() - pe.data_inicio_vigencia)::INT)
  )                                                        AS dias_em_execucao_max,
  EXISTS(
    SELECT 1 FROM lead_contacts lc
    WHERE lc.lead_cnpj = pe.cnpj
    LIMIT 1
  )                                                        AS contact_present
FROM projetos_execucao pe
WHERE ${conditions.join(' AND ')}
GROUP BY pe.cnpj
ORDER BY tem_alerta DESC, total_projetos DESC, pe.cnpj
```

Key design choices enforced by the query:
- `pct_execucao_ponderado` uses `SUM(valor_desembolsado)/SUM(valor_repasse)*100` (weighted, NOT `AVG(pct_execucao)`)
- `dias_em_execucao_max` and `dias_ate_vencimento_min` recomputed from `NOW()` in SQL (NOT stored integers)
- `dias_em_execucao_max` wrapped in `GREATEST(0, ...)` to prevent negative values for future-dated projects
- `contact_present` uses `EXISTS` subquery on `lead_contacts` (NOT a JOIN — avoids GROUP BY complications per Research Pitfall 3)
- No `LIMIT` param needed — the projetos_execucao table has ~8793 rows, grouping by CNPJ reduces to ~2000-3000 rows
- `objeto` column deliberately EXCLUDED from the grouped response (large TEXT field — Phase 17 slide-over fetches it separately)

**Error handling:** Wrap entire handler in try/catch. Log with `console.error('[api/execucao] Query error:', error)`. Return `{ error: 'Failed to fetch execucao data' }` with status 500.

**Return:** `NextResponse.json(rows)` where rows typed as `ExecucaoAggRow[]`.

  valor_global: string | null       // NUMERIC as string

**GET handler:**
- Role guard: same gestor/coordenador check as the list endpoint (401 for others)
- Extract CNPJ from params: `const cnpj = decodeURIComponent(params.cnpj)` (same sanitization as instruments/route.ts)
- Query individual rows for this CNPJ:

```sql
SELECT
  pe.nr_convenio,
  pe.id_proposta,
  pe.situacao,
  pe.modalidade,
  pe.objeto,
  pe.valor_global,
  pe.valor_repasse,
  pe.valor_desembolsado,
  pe.saldo_conta,
  pe.valor_empenhado,
  pe.pct_execucao,
  GREATEST(0, EXTRACT(DAY FROM NOW() - pe.data_inicio_vigencia)::INT)  AS dias_em_execucao,
  EXTRACT(DAY FROM pe.data_fim_vigencia - NOW())::INT                  AS dias_ate_vencimento,
  pe.data_assinatura,
  pe.data_inicio_vigencia,
  pe.data_fim_vigencia,
  pe.alerta_desembolso,
  pe.verificar_saldo
FROM projetos_execucao pe
WHERE pe.cnpj = $1
ORDER BY pe.valor_global DESC NULLS LAST
```

Key notes:
- `objeto` IS included here (unlike the grouped list endpoint) because the slide-over needs it
- `pct_execucao` returns the per-row stored value (not the weighted aggregate — that's the list endpoint's job)
- `dias_em_execucao` and `dias_ate_vencimento` still computed from NOW() for freshness
- `dias_em_execucao` wrapped in GREATEST(0, ...) to avoid negative values

**Error handling:** Same pattern — console.error with `[api/execucao/[cnpj]]` prefix, return 500.
